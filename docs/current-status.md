# TouringHub Current Status

更新日: 2026-10-15

現在の実装状態、既知の課題、次に確認すべきことをまとめます。

## 1. 現在の状態

TouringHub は、静的HTML/CSS/JavaScriptで構成されたツーリング・ドライブ向け地図サイトです。

主な構成:

- エントリーポイント: `index.html`
- スタイル: `style.css`
- 地図ロジック: `conf/map-engine.js`
- 操作ロック: `conf/map-interaction-lock.js`
- 場所検索: `conf/poi-search.js`
- 道の駅ロジック: `conf/michi-no-eki.js`
- 天気ロジック: `conf/weather-engine.js`
- 設定データ: `conf/*.txt`
- 地図データ: `umap_backup_map.umap`、`P35-18_Roadside_Station.geojson`

## 4. 既知の課題・不明瞭な箇所

- `index.html` に設定txt読み込み用のインラインJSが残っています。
- `style.css` とHTML/JS内インラインスタイルの責務が混在しています。
- `map-engine.js` 内に「聖域：ロジック改変厳禁」というコメントがあり、地図周辺の変更は慎重に扱う必要があります。
- `michi-no-eki.js` は自動実行され、`initMap()` からは明示的に呼ばれません。
- `道の駅` は `map-engine.js` のレイヤー設定にも存在し、将来uMap側に同名レイヤーが入ると重複に注意が必要です。
- 天気APIの精度はUI上で注意喚起されています。
- OpenStreetMapタイル利用ポリシー、Cloudflare Analyticsトークン、高速道路ICデータ更新手順は要確認です。

## iPhone Safari向け疑似全画面（2026-10-15）

- Fullscreen APIが存在する環境は従来のネイティブ全画面を優先。API不在またはNotSupportedErrorの場合だけCSS疑似全画面へ移行します。
- 疑似全画面はVisualViewportの位置・幅・高さ（フォールバック100dvh）へ追従し、背景スクロールを固定、解除時に元のスタイルとスクロール位置を復元します。
- 全画面状態を画面ON・雨雲配置・検索ガイドで共有。疑似全画面内では既存のレイヤー凡例を折りたたんで利用できます。

## スマホ全画面UI・グローブ操作（2026-10-15、Issue #1）

- スマホ全画面では「場所を検索」のボタンとパネルを非表示にし、操作ガイドを維持。検索中断・debounce取消・古い応答無効化・フォーカス解除を行い、全画面解除後は閉じた状態で検索を再利用できます。
- Issue #6で現在地を同じDOMのまま地図右下へ独立配置。通常表示の右上は雨雲→追従→全画面、Issue #7以降の全画面は雨雲→ロック→画面ON→追従→全画面解除です。通常表示は44px、全画面は現在地も含め56px/8px間隔を基本に52px/6px → 48px/6px → 44px/4pxへ縮小。現在地の領域を先に確保し、不足時は右上列だけスクロールします。通常表示の検索・PCの既存位置は維持しています。
- 判定は767px以下、または粗い主ポインター＋hoverなし＋画面短辺767px以下。横向きで幅767pxを超えるスマホにも適用し、Wake Lockの767px条件と既存ズーム配置は維持します。
- ネイティブ／疑似の全画面管理は従来どおりです。実機未確認事項・境界ケースはdocs/verification.mdを参照してください。

## スマホ全画面の操作ロック（2026-10-15、Issue #7）

- 透明レイヤー・captureイベント・inert・操作ハンドラ停止を併用し、専用解除UI以外の入力を遮断します。GPS追従・進行方向・雨雲・画面ONは継続します。
- 専用ボタンを最初の有効操作から3秒以内に3回操作すると解除。Pointer/Touch/互換clickの重複を防ぎ、進捗表示とキーボード・支援技術相当の入力にも対応します。
- 非表示・ページ遷移/復帰・全画面終了で解除し、自動再ロックしません。状態はメモリ内のみ。元のinertと操作ハンドラを復元します。
- 実機Safari/Android・支援技術・OSイベントの通知タイミングは未確認です。自動検証と実機を区別した結果はdocs/verification.mdのIssue #7の節を参照してください。
