# TouringHub Decisions

更新日: 2026-06-11

設計判断と、その背景・注意点を記録します。

## 1. 静的サイト構成

決定:

- TouringHub はGitHub Pagesで公開できる静的サイトとして構成する。

理由:

- サーバーサイド処理なしで公開できる。
- 設定txtやGeoJSONをリポジトリ内に置いて読み込める。

注意:

- `fetch()` を使うため、ローカル確認はHTTPサーバー経由にする。
- サーバーサイドAPIや秘密情報を前提にしない。

## 2. Leaflet採用

決定:

- 地図表示は Leaflet 1.9.4 を使用する。

理由:

- 静的サイトで扱いやすい。
- OpenStreetMapタイルと組み合わせやすい。
- MarkerClusterなどのプラグインを利用できる。

注意:

- Leaflet本体やプラグインのCDN障害時は地図表示に影響する。
- 地図操作の独自タッチ制御はLeaflet標準操作と干渉し得る。

## 3. OpenStreetMapタイル利用

決定:

- ベース地図は `tile.openstreetmap.org` を使用する。

理由:

- APIキーなしで利用できる。
- Leafletと標準的に組み合わせられる。

注意:

- 利用ポリシーやアクセス負荷への配慮が必要。
- 大量アクセスが見込まれる場合は代替タイル提供元を検討する。

## 4. uMapデータ固定化

決定:

- uMap由来のデータを `umap_backup_map.umap` としてリポジトリ内で読み込む。

理由:

- GitHub Pages上で静的に読み込める。
- 外部uMap側の状態変化からサイト表示をある程度切り離せる。

注意:

- uMap側との同期手順は明文化が必要。
- `umap_backup_map.umap` はマスタ更新時にファイル全体を置き換える。
- 機能改修や性能改善のために内容、構造、書式を直接編集しない。
- アプリ側の要件は読み込み処理で吸収する。

## 5. 道の駅GeoJSON分離

決定:

- 道の駅は `P35-18_Roadside_Station.geojson` と `conf/michi-no-eki.js` で別読み込みにする。

理由:

- 国土数値情報由来データを独立して扱える。
- uMapデータとは別系統で更新できる。

注意:

- `道の駅` レイヤー名は他のレイヤー設定と重複し得る。
- 2018年データと更新ログに記載があり、鮮度には注意が必要。
- `P35-18_Roadside_Station.geojson` はマスタ更新時にファイル全体を置き換える。
- 機能改修や性能改善のために内容、構造、書式を直接編集しない。
- アプリ側の要件は読み込み処理で吸収する。

## 6. Open-Meteo採用

決定:

- 天気予報は Open-Meteo API を使用する。

理由:

- APIキーなしで利用できる。
- 複数地点の緯度経度をまとめて問い合わせられる。

注意:

- UI上で「海外データにつき精度が不安定」と注意喚起している。
- 出発前の詳細確認用にGoogle天気検索リンクを併設している。

## 7. Google Mapsリンク利用

決定:

- スポット表示、ルート検索、周辺検索はGoogle MapsのURLリンクで連携する。

理由:

- Google Maps APIキーなしで利用できる。
- ユーザーを外部地図アプリ/ブラウザへ誘導できる。

注意:

- Google Maps APIを直接導入する場合は課金・キー管理の検討が必要。
- URL仕様変更の影響は受ける可能性がある。

## 8. 設定txtによるデータ分離

決定:

- 周辺検索、リンク、天気地点、更新ログ、ドロワーは `conf/*.txt` で管理する。

理由:

- HTMLを直接編集せず、設定データだけ更新できる。
- AI作業時のデグレ範囲を狭められる。

注意:

- txt形式はパーサ実装に依存する。
- 形式変更時はJS側とドキュメントを同時に更新する。

## 9. モバイル独自ジェスチャ

決定:

- モバイルでは独自にダブルタップズームと片指ズームを実装する。

理由:

- スマホで片手操作しやすくするため。
- 2回目タップ保持から上下移動でズームできる。

注意:

- 長押しピン、Leaflet標準ジェスチャ、独自ジェスチャが干渉しやすい。
- 変更時は実機またはタッチ相当環境で確認する。

## 10. マスタ地図データの保護

決定:

- `umap_backup_map.umap` と `P35-18_Roadside_Station.geojson` を、置換更新される原本データとして扱う。
- 通常のアプリ改修では両ファイルを直接編集しない。
- 正規マスタによるファイル全体の置換だけを更新として認める。

理由:

- 両ファイルはマスタ更新のたびに置き換えられるため、手作業の変更が次回更新で失われる。
- アプリ固有の加工を原本へ加えると、更新作業とデータ整合性の維持が難しくなる。

注意:

- パフォーマンス改善や表示条件への対応はJavaScript側で行う。
- 元ファイルの手作業による分割、整形、項目追加を運用前提にしない。
- マスタ置換後は形式、参照プロパティ、レイヤー名、件数の互換性を確認する。
