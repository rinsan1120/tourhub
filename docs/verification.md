# TouringHub Verification Guide

更新日: 2026-10-15

変更後の確認観点をまとめます。

## 1. 基本方針

- ローカル確認はHTTPサーバー経由で行います。
- `index.html` の直接オープンでは `fetch()` が失敗する可能性があります。
- 変更範囲に応じて、地図、天気、設定txt、UI表示を確認します。

## 2. ローカル起動

```powershell
python -m http.server 8000
```

ブラウザで開くURL:

```text
http://localhost:8000/
```

## 3. 共通確認

- ページが表示されること。
- ブラウザコンソールに重大なエラーがないこと。
- 外部CDNの読み込みに失敗していないこと。
- GitHub Pages前提の相対パスが壊れていないこと。
- PC幅とスマホ幅で大きな表示崩れがないこと。

## 4. JavaScript変更時

- 可能なら対象JSに対して構文チェックを行います。

```powershell
node --check conf\map-engine.js
node --check conf\weather-engine.js
node --check conf\michi-no-eki.js
```

- ブラウザで該当機能を実操作します。
- 非同期読み込みの失敗時表示も確認します。

## 5. 地図変更時

確認項目:

- 地図が表示される。
- 初期中心と初期ズームが意図せず変わっていない。
- OSMタイルが表示される。
- uMap由来レイヤーが表示される。
- 道の駅が表示される。
- 高速道路ICがズーム条件どおり表示される。
- 凡例チェックで表示/非表示が切り替わる。
- Pointポップアップが開く。
- 名道ポップアップが開く。
- Googleマップリンクが開く。
- 高速/下道ルート検索リンクが開く。
- 緯度経度コピーが動作する。
- 右クリックまたは長押しで仮ピンが置ける。
- 現在地ボタンがエラーなく動作する。
- 全画面ボタンが動作する。
- 座標移動が動作する。
- 読み込み中に進捗表示が出る。
- 表示範囲のデータ生成後に完了表示が出て、自動的に消える。
- データ読み込み失敗時にエラー表示が残る。
- 段階生成中も地図のパンやページスクロールが完全には停止しない。

### 表示範囲連動生成

- 初期表示範囲はデータ読み込み後に即時生成される。
- 初期表示時に表示範囲外のPointが生成されない。
- 先読み範囲が表示範囲の1.4倍である。
- 地図移動終了から1.5秒未満では新しいFeatureが生成されない。
- 地図移動終了から1.5秒以上停止すると、新しい範囲のFeatureが生成される。
- 待機中に移動を再開すると、古い待機タイマーが実行されない。
- 段階生成中に移動を開始すると、古い世代の後続チャンクが生成されない。
- 移動前に生成済みのFeatureが移動後も削除されない。
- 同じ範囲へ戻っても生成済みFeatureが重複生成されない。
- 高速道路ICは表示ズーム条件を満たす場合だけ生成される。

### 段階生成順

- 名道、景勝地、グルメが優先度1として生成される。
- 優先度1の3レイヤーがチャンク単位で交互に生成される。
- その他レイヤー（道の駅を含む）は優先度1の完了後に生成される。
- 高速道路ICは最後に生成される。
- 凡例の表示順は従来どおりである。
- 段階生成中に凡例をOFFにしても、生成完了後に意図せずONへ戻らない。

## 6. モバイル地図操作変更時

### 現在地マーカーの進行方向

- スマホ相当＋追従ONだけで方向表示し、PC・追従OFF・方位未取得では丸表示になる。
- GPS headingの北/東/南/西と360度の正規化、null/undefined/NaN等の座標差分による補完を確認する。
- 5m未満のGPS揺れと停止速度では前回方位を維持し、追従再ONで最後の有効方位が復帰する。
- 位置監視とマーカーが各1つのまま、青丸のpulse・ズーム・北が上の地図を維持する。
- ドラッグによる追従解除、全画面・画面ON・雨雲との併用を確認する。

ローカルHTTP＋ヘッドレスEdgeでGPSとWake Lock・雨雲通信を再現して上記を確認済みです。日付変更線をまたぐ方位計算も確認し、JavaScript例外はありませんでした。実機での走行・停止中のGPS精度と表示は別途確認が必要です。

確認項目:

- 通常のパンができる。
- ピンチズームが壊れていない。
- 長押しで仮ピンが置ける。
- 単純なダブルタップでズームインする。
- 2回目タップ保持から下方向移動でズームインする。
- 2回目タップ保持から上方向移動でズームアウトする。
- 片指ズーム後に指を離し、再度地図へ触れても別地域へジャンプしない。
- 片指ズームを `touchcancel` で終了した後も通常のパンができる。
- 操作ガイドや座標移動UIがタッチ操作を妨げない。

### 画面ONモード（2026-10-01追加）

- スマホ通常表示・PC表示ではボタンとステータスを表示せず、Wake Lockを取得しない。
- スマホ全画面でのみボタンが表示され、既存ボタンや追従時の拡大ズームUIと重ならない。
- 取得成功後だけONになり、保持中はステータスを表示し続ける。OFFでreleaseし、ステータスを隠す。
- 非対応・拒否・再取得失敗ではOFFとなり、地図操作が継続する。
- 非表示や自動releaseでステータスが消え、設定ON・visible・スマホ幅・全画面で復帰した場合だけ再取得する。
- 全画面解除とPC幅への変更ではrelease＋OFF。全画面再開では自動ONにしない。
- 取得中の連打、全画面解除、非表示、幅変更でも遅れて取得したSentinelが残らない。
- 実機でホーム画面、別アプリ、別タブ、電源ボタン、画面ロックからの復帰を確認する。手動消灯を妨げない。
- 現在地・追従・全画面・座標移動・ズーム・パン・レイヤー表示とPC配置に変化がない。

## 7. 天気変更時

確認項目:

- 天気カードを展開できる。
- 最初のエリアが表示される。
- 最初のエリアの天気が取得される。
- タブ切り替えで対象エリアが表示される。
- 未取得エリアの天気が取得される。
- 再取得ボタンが動作する。
- 地点名リンクがGoogle検索を開く。
- 地名で天気検索が新規タブを開く。

## 8. 設定txt変更時

### 共通

- UTF-8で保存されていること。
- `//` コメントで意図しない削除が起きていないこと。
- URL内の `://` が維持されること。

### `weather.txt`

- エリアタブが崩れない。
- 地点行が天気表に表示される。
- 緯度経度がOpen-Meteo APIに渡る。

### `nearby.txt`

- ボタンが表示される。
- Font Awesomeアイコンが表示される。
- Google Maps検索が開く。

### `link.txt`

- カテゴリが表示される。
- リンクカードが表示される。
- `<br>` を含むリンク名の表示が崩れない。

### `drawer-links.txt`

- ドロワー内カテゴリとリンクが表示される。
- 長いURLでもリンクとして開ける。

### `updates.txt`

- 新しい更新が上に表示される。
- `日付 | 内容` の分割が崩れない。

## 11. 雨雲の確認（2026-10-01追加）

- PC/スマホの通常・全画面の4状態でボタンと時間選択を利用でき、現在地・追従・全画面解除・画面ON・ズーム・凡例と重ならない。
- ON直後は最新実況、各時間選択では最も近い予測タイルと実際の日本時間を表示する。
- OFFでタイル・時間UI・出典を消す。通常表示⇔全画面、PC/スマホ幅の切替ではON/OFFと選択中の予測時刻を維持する。
- ON/OFFや時間変更で中心・ズーム・追従・Wake Lock・既存レイヤーの状態を変更しない。
- 切り替え後もズーム・パン・現在地・仮ピン・長押し・ダブルタップ・ルート/スポット操作が使える。
- 320px幅でも時間UIが画面内に収まり、既存クレジットを隠さない。
- 5分以内の再ONと時間変更でJSONを再取得しない。自動更新は画面ON＋雨雲ON＋visibleで10分ごと。非表示中、画面ON OFF、雨雲OFFでは定期取得しない。
- 初回/手動のJSON失敗・無効データ・対応予測なし・タイル失敗・タイムアウトで雨雲だけをOFFにし、控えめなエラーを表示する。自動更新の失敗では旧雨雲を保持する。
- ON取得中にOFFしても、遅れて完了した通信で雨雲が復活しない。

今回の確認: ローカルHTTP＋ヘッドレスEdgeで実JSON/タイルの表示と全時間切り替え、エラー再現、キャッシュ、時刻ずれ、ズームを確認。Wake Lockの同時ON状態はモックで検証済みです。雨雲ON中のダブルタップ、右クリックによる仮ピンも確認しました。長押しはデスクトップEdgeのタッチ再現では雨雲ON/OFFの双方で再現できませんでした。実機での長押し・画面点灯維持・ロック復帰、走行中のGPS追従、GitHub Pages公開後の確認は別途必要です。

利用範囲拡張の確認: PC/スマホの通常・全画面の4状態でON/OFFと全7時刻を確認。通常⇔全画面・画面幅変更で同じ雨雲レイヤー、ON/OFF、選択時刻が維持され、追従・中心・ズーム・既存レイヤーが雨雲操作で変わらないことを検証しました。画面ONとの併用はモックで確認。320px幅、768px幅、横向き740×390px、小さい縦画面320×480pxで既存操作UIとの重なりがないことも確認しました。実通信でも4状態で気象庁のJSON/タイル表示・時間変更・JSONキャッシュを確認し、JavaScript例外はありませんでした。

### 画面ON中の自動更新

- 画面ON＋雨雲ONだけで10分タイマーが1つ開始される。雨雲OFF・画面ON OFF・非表示・pagehideで停止する。
- ON/OFFや画面切替・復帰を繰り返してもタイマーが増えない。
- 全7時刻が新しい基準時刻に対する同じ相対分数へ更新される。
- 復帰時は前回取得から5分未満で再取得せず、5分以上で即取得する。
- 定期JSON失敗・新タイル失敗・各タイムアウトで旧雨雲と更新成功時刻を保持し、次の10分で再試行する。
- 更新中も中心・ズーム・追従・現在地マーカー・既存レイヤー・全画面・Wake Lockが変わらない。
- 「雨雲更新：HH:mm」が成功取得時刻を示し、失敗時に進まない。

ヘッドレスEdgeの仮想時計、Wake Lockモック、更新する時刻JSON、503/404/通信停止を使って上記を確認済みです。取得中OFFとpagehide/pageshowも確認し、JavaScript例外はありませんでした。実通信でPC/スマホの通常/全画面の表示と時間変更、320×480pxの更新時刻UIも確認済みです。実機での長時間表示・OSの画面ロック/バックグラウンド復帰は別途確認が必要です。

### スマホ通常表示のコンパクトバー

- 通常表示だけ地図直下の約72pxバーとなり、320×480、390×844、740×390pxでも地図を覆わない。
- 左右で現在〜+60分を順送りし、端では無効になる。中央には選択分数と実際の時刻が同期する。
- 中央タップ時だけ7時刻の一覧を開き、選択後は閉じる。Escapeでも閉じる。
- 通常⇔全画面や幅変更で選択時刻とレイヤーを維持し、PC通常/全画面とスマホ全画面の既存パネルを維持する。
- 時刻操作で中心・ズーム・追従が変わらず、自動更新・復帰判定・失敗保持が従来どおり動作する。

実通信＋ヘッドレスEdgeで左右・一覧・画面切替・上記3サイズを確認済みです。自動更新の回帰確認も仮想時計とWake Lockモックで実施し、10分更新・復帰判定・タイマー管理・失敗保持が維持され、JavaScript例外はありませんでした。
